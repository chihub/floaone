Yahoo! · Design Lead, Search · 2011 — 2012

The connection that held the verticals together.

Yahoo! in 2011 was redesigning itself around one idea: a decade of separate surfaces made to behave as a single platform. A cross-vertical team set the navigation model that would unify them. I led Search design on that team, and Search was the hardest surface to fit, because it is where a user arrives with a question and no place to be yet.

Image
The throughline

After a decade of surfaces grown on their own schedules, the redesign set out to make Yahoo! move like one platform, governed by a single navigation rule: horizontal across interests, vertical for more of the same, identical on every screen and every property. The team built that rule. I owned the surface that tested it hardest. A search can land a user in any vertical, news, finance, sports, any topic on the platform, so Search is not one more surface to fit. It is the layer that touches all the others. If it moved by the shared rule, the redesign reached the place most users started from. If it did not, the seams reopened everywhere search touched.

The case study

Fitting Search to the shared rule

The problem

The redesign asked every property to move the same way, but search begins before a user has an interest at all, with a query and no place yet. The old search made the gap worse: it returned a page of links disconnected from whatever the user had been reading, and dropped them out of the content stream the redesign was building everywhere else. The problem was never the results page. It was the missing layer between search and the content every other vertical owned.

Image

Every other surface starts with a place. Search starts with a question.

The response

The rule came first. Horizontal movement navigates across interests, and vertical gives more of the same within one, carried on two levels: the Base Level held interest landing pages arranged left to right, and the River Level held the content cards a user reads within an interest. The team stress tested it against real user stories and four screen sizes before anything was built on top of it. My question was narrower and harder: how does search, which starts before a user has any interest at all, live inside a rule built entirely around interests?

Image
Image

What the team built

Two things sat on top of the rule: the team's content system and the search framework I led. The content system named six card archetypes as the building blocks of every river, Landing, Article, Photo Gallery, Video Gallery, Ad, and List, and the team proved the set by building three very different rivers, a 49ers river, a Natalie Portman river, a Snowboarding river, from the same six pieces. That was the platform's shared vocabulary, and Search had to speak it.

The framework I designed treated a search as a way into the platform rather than a detour out of it, in four parts. A mixed source results page drew web, Yahoo! content, and publishers into one view, so a single query reached across the platform's content. A context aware search box shaped results around where the user already was. Search generated contextual content turned any result into a doorway into a topic river, so a search became an interest and the user moved on by the same horizontal and vertical rule as everywhere else. And search navigation through an Interest Store let a search be saved and followed, turning a one time query into a standing interest.

Three principles held it together: discovery as the governing force, the sense that there is always something next; satisfaction and curiosity, serving the user who knows exactly what they want and the one who does not; and curation, branching, and infinite browsing, giving the user control over the stream. Carried across tablet, browser, and phone, search became a way to move through the product instead of a place to leave it.

Image

How the team worked

The Design Innovation team pulled designers from across Yahoo!'s surfaces into one room with one mandate: build the architecture the whole company could share. I held the Search seat. A rule meant to govern every property could not be authored inside any one of them without carrying its bias, so it came from a team that answered to the platform. The work happened on the wall before the screen: breaking the existing experience apart in working sessions, stress testing the rule against user stories, then prototyping for desktop, tablet, and mobile to feel whether the logic held in the hand. If the structure could hold search, it could hold anything.

Image

The outcome

Yahoo! got one navigation rule across every surface and device, and Search became the layer that tied the verticals together. A query inherited the user's context, a result opened into a topic river owned by another team, and from there the user moved by the same rule as everywhere else. The surface most likely to break the unified experience became one of the surfaces that held it together.

Platform context (team)
One navigation rule, horizontal across interests and vertical for more, governing every Yahoo! surface and device through two levels, Base and River, with a six archetype card system as the shared content vocabulary
Search, made the connective layer
The search framework I led: a four part model, mixed source results, a context aware search box, search generated contextual content, and search navigation, that turned search from a detour out of the platform into the connection between its verticals
The fit across the platform
A query inherited the user's context and a result opened into a topic river owned by another team, so search handed off coherently into every vertical and moved by the same rule as the rest of the platform, across tablet, browser, and phone
Image

The same systems thinking later carried into a separate Search initiative, a navigation redesign across desktop and mobile aimed at global navigation and advertising revenue. That work produced $40M in quarterly revenue growth.

Close

Every platform has one connection that decides whether the whole thing coheres, and it is rarely the one on the org chart. At Yahoo! it was search. Finding that connection early, and designing it before the seams show, is the habit this work built.
